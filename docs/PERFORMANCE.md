# Измерения производительности — 0.6.0

Настройки → Note Bridge → Скорость синхронизации: просмотр последних 10 циклов и экспорт всех сохранённых замеров в JSON. Также доступны команды просмотра и экспорта. Хранятся последние 200 записей на каждом устройстве в каталоге плагина `state/performance`. Они не отправляются в Drive. Экспорт создаёт файл `Note Bridge Journal Performance … .json` в хранилище; он также исключён из синхронизации. Его можно приложить для анализа.

## Локальный индекс

Хеш, размер, время изменения/создания и дата проверки сохраняются между запусками. Неизменившиеся файлы не читаются заново для индексации. События изменения инвалидируют соответствующие пути. При первом запуске после обновления индекс заполняется. Обход метаданных в памяти остаётся O(N), но чтение содержимого и хеширование обычно нужны только изменившимся файлам.

Раз в семь дней содержимое каждого файла перепроверяется при следующем сканировании. Команда полной локальной проверки делает это принудительно. Внешнюю правку, сохраняющую размер и обе временные метки, метаданные не обнаружат до такой проверки. Контроль реального содержимого перед перезаписью/удалением сохранён. Индекс — ускорение, а не доказательство отсутствия изменений.

## Поля JSON

- `wallMs`: длительность всего цикла, включая начальную запись маркера и финальное сохранение состояния, но без записи итогового технического отчёта.
- `local_check`: проверка локального индекса; `local_content_read`: чтение содержимого для этой проверки. Счётчики `local_files`, `local_cache_hits`, `local_hashed`, `local_hashed_bytes` показывают объём работы; посещения не обязательно уникальны за цикл.
- `drive_check`: время получения/обновления индекса Drive. `drive_change_pages`, `drive_changes_received`, `drive_listing_pages`, `drive_listing_items` показывают запросы и объём ответов. Лента изменений аккаунта может содержать записи вне выбранной папки.
- `rates`: локальные посещения файлов/с, размер обработанного индекса Drive/с и полученные изменения Drive/с. Размер индекса не равен количеству скачанных файлов или сетевых ответов.
- `note_upload`, `note_download`: передача содержимого. Чтения могут включать данные для истории/конфликтов, не только применение заметок на устройстве.
- `history_upload`, `verification_download`, `index_content_download`: история, контрольное скачивание после записи, получение хеша при индексации — отдельно от обычной передачи.
- `operation_upload`, `operation_download`: операции целиком, включая проверки, историю и подтверждение состояния. Это полезнее для оценки времени появления готовых заметок.
- `authorization`, `drive_metadata`, `retry_wait`, `state_record`, `state_snapshot`: авторизация, служебные запросы, ожидание повторов и запись локального состояния.

В каждой метрике: `completed`/`failed`, байты полезного содержимого, сумма длительностей `totalMs`, объединённое время активности `activeMs`, максимум и p50/p95 длительности последних максимум 256 завершённых попыток. Параллельные интервалы в `activeMs` учитываются один раз. Скорость в байтах/с рассчитывается по успешным байтам и времени активности, а не по всей длительности цикла; не включает HTTP/TLS-накладные расходы. Ошибочные попытки увеличивают время, но не успешные байты. Нулевая/неизвестная скорость обозначается `null`.

Этапы вложены и перекрываются: их времена нельзя суммировать для получения `wallMs`. При выгрузке приложения остаётся начальный маркер: завершившиеся этапы могут отсутствовать, длительность прерванного цикла неизвестна, а не равна нулю. В отчётах нет имён/содержимого заметок, ID Drive, токенов или текстов ошибок.

Для сравнения соберите на одном устройстве несколько циклов без изменений, изменение одной заметки и пакет изменений. Сравнивайте одинаковые сценарии, сеть и состояние приложения. Тесты подтверждают расчёты и отсутствие повторных чтений на модели 1000 неизменившихся файлов; это не замер скорости iPhone.
