# Настройка тестовой версии

## Что уже развёрнуто

Worker: https://note-bridge-auth.pravoepredserdie.workers.dev

Проверка: https://note-bridge-auth.pravoepredserdie.workers.dev/health

D1: `note-bridge-auth`, таблицы sessions/devices. Учётные данные Google пока не добавлены; сервис возвращает configured=false и не начинает авторизацию.

## Google Cloud — нужен владелец аккаунта

1. Создать отдельный Google Cloud-проект и включить Google Drive API.
2. Настроить Google Auth Platform / OAuth consent. Для теста добавить свой аккаунт в test users.
3. Создать OAuth client типа Web application.
4. Добавить **точный** Authorized redirect URI:

   `https://note-bridge-auth.pravoepredserdie.workers.dev/callback`

5. Scope: `openid`, `email`, `https://www.googleapis.com/auth/drive`.
6. Сохранить Client ID и Client secret в секреты Worker через интерфейс Cloudflare, не отправляя в чат и не помещая в код.

Секреты Worker:

| Имя | Значение |
|---|---|
| GOOGLE_CLIENT_ID | ID web OAuth-клиента |
| GOOGLE_CLIENT_SECRET | Его секрет |
| ALLOWED_EMAIL | Единственный разрешённый Google email |
| PAIRING_CODE | Случайный код подключения, минимум 32 символа |
| TOKEN_ENCRYPTION_KEY | 32 случайных байта, закодированные base64url |

Код подключения и ключ шифрования можно сгенерировать локально из криптографического генератора. Не используйте один и тот же секрет для обоих полей. В следующем шаге настройки агент может сам создать и установить ключ шифрования через Cloudflare; пароль/секрет Google владелец вводит непосредственно в Cloudflare.

Testing в Google обычно ограничивает срок refresh token семью днями для этих scopes. Перед ежедневным использованием нужно отдельно проверить переход приложения в production для personal use и предупреждения Google. Публикация плагина в каталоге Obsidian к этому не относится.

## Подключение устройств

1. Создать отдельную тестовую папку в My Drive и две тестовые заметки .md.
2. Создать новое локальное хранилище Obsidian на каждом устройстве.
3. Установить плагин, открыть его настройки.
4. Адрес Worker уже заполнен. Вставить ID папки (из ссылки /folders/ID).
5. Ввести PAIRING_CODE, нажать «Подключить», подтвердить Google в браузере.
6. Вернуться в Obsidian, нажать «Завершить подключение».
7. Сначала «Предпросмотр», затем «Синхронизировать».
8. Автосинк оставить выключенным до завершения приёмки.

Папка привязывается к локальной базе синхронизации. Для другой папки используйте другое тестовое хранилище; молчаливого сброса состояния нет.

## Обязательная приёмка на реальных устройствах

- Новый пустой телефон получает заметки, ничего не удаляя в Drive.
- Правка на телефоне видна в Drive и на ноутбуке.
- Внешняя правка существующего .md через режим «Работа» приходит на телефон.
- Новый .md, загруженный извне, приходит на оба устройства.
- Одновременная правка одного абзаца сохраняет оба варианта.
- Google Drive действительно отклоняет обновление с устаревшим If-Match (HTTP 412).
- Если файл меняется после чтения и до отправки, чужая новая версия не затирается.
- Отключение сети в середине операции не приводит к удалению/перезаписи без сохранённой копии.
- Изменение локального текста во время скачивания не теряется.
- На iPhone работают requestUrl, SecretStorage, SHA-256 и возврат из браузера.
- Проверить поведение после приостановки/выгрузки приложения и после истечения access token.

До выполнения этих пунктов сборка остаётся experimental. Изменения/удаления больших вложений, переименование и восстановление истории будут отдельными этапами.

## Повторное развёртывание

После настройки Wrangler-доступа:

```sh
npx wrangler d1 execute note-bridge-auth --remote --file auth-service/schema.sql --config auth-service/wrangler.jsonc
npx wrangler deploy --config auth-service/wrangler.jsonc
```

Секреты задаются интерактивно `wrangler secret put NAME --config auth-service/wrangler.jsonc` либо в Cloudflare dashboard. Не передавайте значения через аргументы командной строки.
