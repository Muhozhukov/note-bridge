# Note Bridge 0.2.0 — experimental

## Изменения

- События переименования файлов и папок в Obsidian сохраняются в очередь. При синхронизации Drive получает изменение имени/родителя, сохраняющее ID и содержимое. Состояние очереди сохраняется до сетевого запроса, чтобы восстановиться после потерянного ответа.
- По стабильному ID Drive обнаруживается удалённое переименование файла: локальная неизменённая копия перемещается с обновлением ссылок средствами Obsidian. Пустые старые локальные папки перемещаются в локальную корзину. Если одновременно изменилось содержимое, операция блокируется для ручного разбора.
- Автосинхронизация включается при переходе на эту версию (однократная миграция), далее уважает настройку пользователя. Запуск через 3 секунды после изменения, на старте/возврате и каждые 2 минуты. Изменения во время синка ставят следующий проход в очередь. Служебные локальные записи плагина не запускают бесконечную синхронизацию.
- Иконка синхронизации вращается во время работы.
- Новый раздел «Конфликты и удаления»: из окна прогресса, настроек и палитры команд. Выбор версии телефона/Drive, восстановление удалённого файла или подтверждение удаления. Перед заменой содержимого сохраняется снимок; удаление в Drive — только в корзину, локальное — в локальную корзину.
- Точные дубликаты папок верхнего уровня предлагаются отдельно. Удаление возможно после явного подтверждения и повторной проверки: старая папка отсутствует локально, набор файлов и хеши полностью совпадают с новой папкой Drive и локальной копией. Изменившиеся версии, служебные файлы и неподдерживаемые объекты блокируют действие.
- До трёх параллельных передач. При сбое новые задания не стартуют, запущенные дожидаются завершения перед снятием блокировки. Одновременное создание общей папки объединено в один запрос.
- Новые загрузки не создают лишний снимок в истории; успешная запись проверяется SHA-256 из ответа Drive, если доступен, иначе чтением обратно. Снимки перед перезаписью сохранены.

## Проверка

65 автоматических тестов, TypeScript и сборка. Тесты покрывают сравнение, переименование по ID, коллизии, восстановление после потерянного ответа переименования, отбор дубликатов, условную запись/корзину, общий запрос создания папки и завершение параллельных операций после ошибки.

Тесты Google используют подменённые ответы. OAuth и обычные передачи в предыдущих версиях подтверждены пользователем на iPhone. Новые операции переименования и корзины, UI и скорость ещё требуют проверки на реальном устройстве. Worker не изменён.

## Ограничения

- На iOS нет гарантированной работы после сворачивания/блокировки. Автосинк работает при активном Obsidian, прерванный запуск возобновляется после возврата.
- Переименования, сделанные до установки обновления, не реконструируются по догадке: существующие дубликаты разбираются в новом окне.
- Переименование до первой общей синхронизации или одновременно с внешними изменениями пути может потребовать ручного разбора. Передачу спорного переименования можно отменить в окне, не меняя файлы.
- Автоматическое удаление без подтверждения не включено. Нет автоматического слияния текста. Замена существующих двоичных вложений пока требует ручной проверки. Лимит — 10 МиБ на файл.
- Drive не предоставляет транзакцию на целое дерево: проверки перед корзиной уменьшают окно гонки, но не блокируют другие устройства. При разборе дубликатов не редактируйте эти папки с другого устройства; корзина сохраняет возможность восстановления.
- Полная сверка остаётся; Changes API пока не используется.
