# Note Bridge 0.4.0 — experimental

## Инкрементальная синхронизация

- После первой полной проверки сохраняется индекс Drive и курсор Changes API. Следующие циклы получают только изменения: редактирование одной заметки не вызывает обход всех папок или скачивание остальных заметок.
- Все страницы ленты обрабатываются до фиксации нового курсора. Ошибка не превращается в удаление файлов. Полная проверка берёт начальный курсор до обхода, чтобы не потерять изменения во время обхода.
- Локальные хеши кэшируются в памяти по mtime/размеру с инвалидированием событиями Obsidian. При перезапуске локальные файлы хешируются один раз. Перебор метаданных и сравнение сохранённых индексов в памяти остаются линейными; содержимое неизменённых файлов повторно не читается.
- Создание проверяет совпадения запросом по конкретному имени, а не выгружает список всех соседних заметок.
- Полный обход папки хранилища остаётся при первом запуске, изменении структуры папок, восстановлении недоступного курсора и команде «Полная перепроверка индекса». Эта версия не делает инкрементальную перестройку отдельных поддеревьев.

## Планировщик и интерфейс

- Автосинк после 30 секунд без локальных правок, не чаще раза в минуту. Периодическая проверка Drive сохраняется (обычно раз в 120 секунд). Непрерывный набор откладывает автосинк до паузы; ручной запуск немедленный.
- Иконка открывает статус, не запускает синхронизацию. Запуск — отдельная кнопка. Последний результат сохраняется при перезапуске.
- Пока открыты статус/конфликты, автоматический запуск приостановлен. Просмотр конфликтов использует сохранённый индекс; отдельная кнопка проверяет изменения в Drive. Список может устареть, но применение повторно проверяет версии.
- Решение конфликта блокирует повторные нажатия, показывает выполнение, подтверждает успех и сразу обновляет список без нового запуска синхронизации.
- Неразрешённый конфликт с неизменившимися версиями больше не создаёт одинаковые снимки и повторные уведомления каждый цикл.

## Удаления

- События локального удаления записываются в журнал ожидающих удалений. Если файл ранее был синхронизирован и Drive сохранил тот же ID и хеш, он автоматически переносится в корзину с условием на текущую версию/ETag.
- Если версия Drive изменилась, файл заменён другим ID или нет записи о локальном удалении, требуется решение пользователя. Даты часов устройств не определяют победителя.
- Явное событие корзины Drive может автоматически удалить неизменённую локальную версию. Потеря доступа не считается подтверждённым удалением. При полной перестройке или прерывании до применения такого удаления возможна ручная проверка.
- Старые удаления до установки 0.4.0 не имеют записей о событии, поэтому останутся на ручном разборе. Пустые папки после удаления файлов могут остаться в Drive.

## Проверка и ограничения

Проверены TypeScript, сборка и автоматические тесты: пагинация и атомарность курсора, единичная правка среди 1001 заметки, сторонние изменения Drive, переименование файлов, дубликаты имён, перестройка папок, безопасное удаление и повторный конфликт. Google API подменён в тестах; реальные скорость и интерфейс на iPhone требуют проверки после обновления.

Построчное разрешение конфликтов из 0.3.0 сохранено. Лимит файла 10 МиБ. iOS по-прежнему может приостанавливать Obsidian в фоне. Worker и Google OAuth менять не нужно.
