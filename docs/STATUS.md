# Note Bridge 0.5.0 — experimental

## Надёжность и восстановление

- Служебное состояние мигрирует из data.json в каталог state внутри каталога плагина. Записи журнала неизменяемы, имеют контрольную сумму и проверяются перед подтверждением. Полный снимок создаётся на границах цикла/проверок и при отдельных изменениях настроек, а не после каждого синхронизированного файла.
- Запись намерения завершается до отправки запроса. Для новых файлов, папок и снимков заранее резервируются Drive ID. При потерянном ответе можно проверить ранее выделенный ID, не создавая новую копию вслепую. Это не устраняет конфликт независимого создания одного пути разными устройствами.
- Курсор Drive сохраняется вместе со свидетельствами удаления. Перезапуск и просмотр изменений больше не теряют подтверждённое удаление.
- Восстановление подтверждает завершившиеся загрузки и скачивания по плану и хешам. Неоднозначные состояния по-прежнему могут требовать разбора конфликта. Нет обещания транзакции между устройством и Google Drive.
- Ошибки отдельных файлов не блокируют независимые файлы; ошибки сети, авторизации и журнала останавливают цикл. Повторы чтения используют увеличивающуюся задержку со случайной добавкой. Ответ 401 допускает однократное обновление токена.
- Подавление событий собственных операций ограничено затронутыми путями вместо глобального подавления всех пользовательских событий.
- Удаление дубликата переносит проверенные файлы в корзину по одному с контролем версий. Новые потомки не захватываются удалением родительской папки. Пустые папки остаются для ручной уборки.

## Производительность

- Переименование/перемещение известной папки пересчитывает пути по связям ID без обхода Drive. При добавлении папки извне читается только новое поддерево. Все страницы изменений и необходимые поддеревья должны успешно загрузиться до фиксации индекса.
- Новые снимки истории — один файл содержимого с JSON-описанием в поле description. Отдельный JSON-файл на каждый снимок больше не создаётся. Снимки дедуплицируются по хешу на устройстве; разные устройства ещё могут создать одинаковые снимки.
- При обычной отправке изменённого файла сохраняется предыдущая версия; избыточный предварительный снимок новой версии убран. Кэш общей версии позволяет не скачивать предыдущий текст из Drive ради истории.
- В тёплом сценарии обновление файла требует около четырёх запросов: снимок или проверка существующего снимка, проверка ETag, запись, проверочное скачивание. Отдельно учитываются лента изменений, получение OAuth-токена, подготовка папки истории и пакетное резервирование ID. Это анализ цепочки, не замер iPhone.
- Запись файлов обновляет индекс по ID без фильтрации всего массива на каждую загрузку. План выполнения содержит изменённые/требующие согласования записи; сортировка всех путей убрана.
- В журнал добавлена статистика запросов и байтов Drive. Время запросов суммируется, а не является полной длительностью синхронизации; неуспешные запросы могут не иметь измеренного времени ответа.

## Слияние текста

- Общая синхронизированная версия хранится в локальном кэше. Независимые изменения Markdown/TXT могут объединяться автоматически; пересекающиеся и касающиеся границ изменения остаются на ручном разборе. Оба изменённых оригинала сохраняются до автоматического слияния.
- Кэш ограничивает размер отдельного объекта 1 МиБ, удаляет объекты, не нужные текущим базовым версиям и незавершённым записям. Общего лимита кэша в байтах пока нет. Восстанавливаемые общие версии проверяются по SHA-256.
- Для длинных текстов добавлены patience-якоря с ограниченным LCS в промежутках. Сильно различающиеся тексты без подходящих якорей всё ещё могут потребовать внешнего редактора.

## Проверки и оставшиеся ограничения

Автоматические проверки охватывают журнал и его прерывания, потерянный ответ создания, сохранение удалений после перезапуска, переименование папок без листинга, импорт нового поддерева, потерю доступа, три стороны сравнения, длинные тексты и изоляцию ошибок файлов. TypeScript и сборка входят в CI. Google и файловый адаптер моделируются в тестах; отказ накопителя и реальная работа UI на iPhone этими тестами не подтверждены.

Метаданные всего хранилища всё ещё обходятся в памяти за цикл; при холодном запуске локальные файлы хешируются для проверки изменений вне приложения. Полностью O(число изменений) обработка не заявляется. Параллельность остаётся ограниченной тремя задачами; адаптивный регулятор и возобновляемая передача больших вложений пока не внедрены. Лимит файла 10 МиБ. iOS может приостанавливать приложение в фоне.

Старый data.json после миграции не обновляется. Не удалять state и не переносить между устройствами; прямой откат на старую версию будет использовать устаревшее состояние. Повреждённый подтверждённый журнал блокирует загрузку вместо автоматического сброса истории синхронизации. Worker и Google OAuth не меняются.
